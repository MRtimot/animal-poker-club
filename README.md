> 诈唬、策略与动物之间的较量 —— 今天，谁才是真正的扑克王？

**创始人：Timothy Ong — Founder of APEX**

一个真正可以玩的 **3D 动物德州扑克** 网站：3D 动物角色 + 动物创建器 + 完整德州扑克规则 + 动画 + 本地 AI + 自建服务器在线多人房间。

- 全中文界面

## 快速开始

需要 Node.js 22.13 以上（推荐 24；账号系统使用 Node 内置的 SQLite。本机已安装在 `~/.local/node`）。

```bash
npm install
npm run dev        # 同时启动游戏服务器（3001）和网页（5173）
```

打开 <http://localhost:5173>。同一局域网内的其他设备可以用终端里显示的 `Network` 地址访问。

### 生产部署（真正的跨国在线对战）

```bash
npm run build      # 构建网页到 dist/
npm start          # 一个进程同时提供网页 + WebSocket（默认端口 3001，可用 PORT 修改）
```

把项目部署到任何一台有公网 IP 的服务器（VPS），马来西亚、中国、新加坡的玩家打开同一个网址，输入同一个房间代码（例如 `ABCD12`）就能一起玩。
如果网页和游戏服务器不在同一个地址，可以在「设置 → 在线服务器地址」里填写，例如 `wss://poker.example.com/ws`。
使用 HTTPS 时请在前面加一层反向代理（如 Nginx / Caddy）并转发 `/ws` 的 WebSocket。

### 免费部署（RM0）：全部放在 Vercel

网页、实时连接（WebSocket）都在 Vercel 上运行。因为 Vercel 同一时间可能有多个函数实例，房间状态保存在一个免费的 Redis 里，任何实例都能接手。

1. **导入项目**：Vercel → Add New → Project → 导入本仓库（项目自带 `vercel.json`，不需要改任何构建设置）。
2. **添加免费 Redis**：在项目里打开 Storage（或 Marketplace）→ 选择 **Upstash Redis** → Free 方案 → Connect 到这个项目。它会自动添加 `KV_URL` / `REDIS_URL` 等环境变量，不需要手动复制。
3. **重新部署一次**（Deployments → Redeploy），让新的环境变量生效。
4. 打开你的 Vercel 网址，一台设备创建房间，另一台输入房间代码加入。

确认 Settings → Functions 里 **Fluid Compute 是开启的**（2025 年 4 月之后创建的项目默认开启），Vercel 的 WebSocket 需要它。

工作方式：

- 实时连接：`/api/ws`（`api/ws.js`，由 `server/vercel.ts` 打包生成；修改服务器代码后运行 `npm run build:api` 并提交）
- Vercel 免费方案每条连接最长 300 秒：网页会在到期前自动换一条新连接，牌局不中断
- 每次房间变化只消耗 1 条 Redis 命令（版本号比较 + 写入 + 广播在同一个脚本中完成）

| 项目 | 成本 | 说明 |
| --- | --- | --- |
| 网页 | 免费 | Vercel（Hobby 免费方案）托管静态网页 |
| 实时连接 | 免费 | Vercel Functions 的 WebSocket（Hobby 方案可用） |
| 房间状态 | 免费 | Upstash Redis 免费方案（通过 Vercel 应用市场添加） |
| 实时通信 | 免费 | 自建 WebSocket（`ws` 开源库），不使用任何付费多人联机服务 |
| 数据库 | 不需要 | 玩家进度保存在各自浏览器，可导出 / 导入；Redis 只保存进行中的房间（30 分钟无活动自动过期） |
| HTTPS | 免费 | Vercel 自带证书 |
| 密钥 / API Key | 无 | 默认配置不需要任何密钥 |

免费方案的限制（以官方文档为准，部署前请再核对一次）：

- **Vercel Hobby**：每月 4 小时实际运算时间（只在处理消息时计算）、100 万次调用、360 GB·小时内存；单条连接最长 300 秒。超出后 Vercel 会暂停网站 30 天，**不会扣费**
- **Upstash Redis 免费方案**：每月 50 万条命令、10 GB 流量、256 MB 存储。本游戏每手牌大约消耗几十条命令，朋友之间玩足够
- 服务器重新部署时，进行中的连接会断开后自动重连；房间保存在 Redis 中，不会丢失

也可以不用 Redis，改用 Render 免费服务（`render.yaml`）运行单个服务器，房间保存在内存中；网页放 Vercel 时设置 `VITE_GAME_SERVER` 指向 Render 网址、在 Render 设置 `APC_ALLOWED_ORIGINS`。

服务器很轻量：只在有人操作时同步牌局事件，不同步 3D 动画、镜头或每一帧画面；空房间 10 分钟后自动清理。

### Google 登录与云端存档（可选）

> 默认关闭。账号系统需要能永久保存数据的服务器磁盘（免费的 Render 方案没有），只有设置了 `GOOGLE_CLIENT_ID` 才会启用并创建数据库。

不配置也能玩：玩家以游客身份游玩，进度保存在本机浏览器。要开启「使用 Google 登录」：

1. 打开 [Google Cloud Console → API 和服务 → 凭据](https://console.cloud.google.com/apis/credentials)，创建「OAuth 客户端 ID」，类型选「Web 应用」。
2. 「已获授权的 JavaScript 来源」填写你的网站地址，例如 `https://poker.example.com`（本地测试加上 `http://localhost:5173` 和 `http://localhost:3001`）。不需要填写重定向 URI。
3. 启动服务器时设置环境变量（客户端 ID 是公开值，不是密钥，不需要客户端密钥）：

```bash
GOOGLE_CLIENT_ID=xxxxxxxx.apps.googleusercontent.com npm start
```

| 环境变量 | 作用 |
| --- | --- |
| `GOOGLE_CLIENT_ID` | Google OAuth 客户端 ID；不设置则不显示 Google 登录 |
| `APC_DB_PATH` | 玩家数据库文件位置，默认 `data/apc.sqlite`（请定期备份；已加入 .gitignore） |
| `APC_ALLOWED_ORIGINS` | （服务器）允许连接的网页地址，例如你的 Vercel 网址；支持 `https://*.vercel.app` 通配（会允许所有 Vercel 网站，不推荐）。不设置则不限制来源 |
| `REDIS_URL` / `KV_URL` | （Vercel）Redis 连接地址，添加 Upstash Redis 后由 Vercel 自动设置；也支持 `KV_REST_API_URL` + `KV_REST_API_TOKEN` |
| `VITE_GAME_SERVER` | （网页构建时）游戏服务器地址，例如 `https://xxx.onrender.com`；不设置则连接网页所在的网址 |
| `APC_DEV_LOGIN=1` | 仅开发环境：显示「测试登录」，不需要 Google 即可测试账号功能；正式环境（`NODE_ENV=production`）永远关闭 |

正式环境请使用 HTTPS（反向代理需转发 `X-Forwarded-Proto`），登录 Cookie 会自动带上 `Secure`。

## 安全设计

- 服务器是**唯一的权威游戏状态**：洗牌（`crypto.getRandomValues`）、发牌、行动校验、底池、边池、胜负都在服务器完成
- 每个客户端只会收到**自己的底牌**；其他玩家的底牌在摊牌前不会离开服务器（有测试验证）
- 客户端只能发送“我要跟注 / 加注 X”这类意图，非法操作会被拒绝
- 每个动作带唯一 ID：疯狂点击或网络重发，同一个动作只会执行一次；过期（上一手牌）的动作会被拒绝
- 限流：建房 / 加入、聊天、牌局动作、重连分别限速；每个 IP 的连接数有上限；明显刷屏的连接会被断开
- 每个浏览器标签页是一名独立玩家；刷新页面会回到原来的座位，短暂断网不会被踢出牌局
- 玩家名字、角色配置、聊天内容在服务器端都会做长度与格式校验

### 账号安全

- Google 登录：服务器验证 ID Token 的签名（Google 公钥）、签发者、受众（客户端 ID）、过期时间和一次性 nonce；我们从不接触 Google 密码
- 内部玩家 ID 由服务器随机生成，与 Google ID / 邮箱无关；不保存邮箱；前端看不到 Google ID、Token 或数据库 ID
- 登录会话使用 `HttpOnly + SameSite=Lax`（HTTPS 下加 `Secure`）Cookie，数据库只保存会话令牌的 SHA-256 摘要
- **经验、等级、筹码、成就、解锁内容只能由服务器结算**：登录玩家的 AI 对局也在服务器上运行；客户端只能修改昵称、外观和设置，任何其他字段都会被拒绝
- 每一手牌 / 每一场比赛都有唯一结算键，重复结算不会重复发奖；XP、等级、成就、筹码在同一个数据库事务中写入
- 多设备：进度只由服务器原子累加，不会被旧设备覆盖；外观修改带版本号，冲突时在最新数据上重新应用
- 游客存档迁移：每个账号只迁移一次，经验封顶 10 级，统计做一致性检查，成就由服务器重新判定
- 写操作校验请求来源（防跨站请求伪造），登录接口限流；出错时只显示通用中文提示，不暴露技术细节

```

│   ├── blackjack/        21 点：规则、牌靴、引擎、控制器、AI 策略、庄家与台词

├── animation/            动物动画姿态、事件导演（事件 → 动作 / 筹码 / 镜头 / 音效）

├── ui/                   首页、扑克大厅、在线房间、创建器、游戏 HUD、收藏、设置
├── progress/             等级、成就、奖励规则（服务器与游客共用）
├── account/              账号接口客户端
├── audio/                本地合成音效与音乐
└── store/                Zustand 状态
server/                   自建 Node.js 服务器
├── index.ts              HTTP + WebSocket 入口
├── rooms.ts              房间与牌局（通过 AccountLink 接口把结算交给账号系统）
├── api.ts                账号 HTTP 接口（/api/auth/*、/api/player/*）
├── auth/                 Google ID Token 验证、登录会话
├── account/              玩家档案、进度、收藏、成就、统计、设置、结算
└── db/                   内置 SQLite 数据库（node:sqlite）与结构迁移
tests/                    Vitest 测试
```
