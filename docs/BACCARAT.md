# BACCARAT 百家乐开发文档

百家乐（Punto Banco）是俱乐部的第三个游戏模式。它和德州扑克、21 点共用房间、账号、存档、音频、3D 俱乐部、动物、镜头与页面（`screen: 'game'`），
新写的只有规则、牌靴、引擎、控制器、桌面布局、HUD 和外观选项。没有付费服务，没有真钱，只有虚拟金币 / 筹码。

## 1. 规则（`src/core/baccarat/rules.ts`，V1 锁定）

| 规则 | 设定 |
| --- | --- |
| 牌靴 | 8 副标准 52 张（416 张）；剩余少于 16 张（切牌位置）时，**下一局开始前**换新牌靴并重新洗牌；一局中途绝不洗牌（一局最多用 6 张） |
| 洗牌 | Fisher–Yates，随机数只用 `crypto.getRandomValues`（没有就报错，不退回 `Math.random`） |
| 点数 | A = 1，2–9 按牌面，10 / J / Q / K = 0；一手的点数只取个位数 |
| 发牌顺序 | 闲 1、庄 1、闲 2、庄 2，然后按补牌表决定第三张 |
| 例牌 | 任何一方前两张是 8 或 9：双方都不再补牌 |
| 闲家补牌 | 0–5 补，6–7 停 |
| 庄家补牌 | 闲家没补：0–5 补，6–7 停。闲家补了：0–2 补；3 除非闲第三张是 8；4 闲第三张 2–7；5 闲第三张 4–7；6 闲第三张 6–7；7 停 |
| 赔付 | 闲 1:1；庄 1:1 抽 5%（盈利 = 下注 × 95%，向下取整）；和 8:1；开和时押闲 / 庄的下注退回本金 |
| 边注 | **V1 没有**（对子、龙宝等都没有实现，界面里也没有） |
| 下注 | 每局一次、确认后不能修改；可以同时押多个区；每个有下注的区不少于最低下注，总额不超过最高下注与余额 |
| 离桌 | 下注阶段离开：退回下注。停止下注后离开：结果已经确定，**按真实结果照常结算一次**（可能赢也可能输） |

赔率与抽水写死在规则里：`cleanBacRules` 只接受牌靴与限额参数，任何配置都改不了 1:1 / 5% / 8:1。

限额：单人桌三档（休闲 10–500 / 俱乐部 50–2,000 / 贵宾 200–10,000）；在线房间最低下注 = 房间的大盲，最高 = 初始筹码。

## 2. 牌靴与引擎（`shoe.ts`、`engine.ts`，纯逻辑）

- 牌靴只依赖“牌”和“随机数”两个模块，读不到玩家、下注、余额、等级、动物、外观、连胜连败或庄家性格。
- 每张实体牌有唯一编号（`uid`，例如 `Kh-3` = 第 4 副的红心 K），同一张牌不会在一个牌靴里出现两次。
- **停止下注的那一刻整局的牌就发好、结果就确定了**（`dealCoup`）；之后的“逐张开牌”只是把已经确定的牌按顺序公开。
  画面、动画、跳过演出、断线、刷新都不可能改变结果。
- 状态机：`betting → closed → dealing → settled → round-end`（见 `types.ts`）。非法跳转抛错（程序 bug），非法操作抛 `BaccaratError`（给玩家看的原因）。
- 筹码守恒：余额 + 桌上下注 + 派彩在任何一步都可以核对；状态可以 `JSON.stringify` 保存，服务器换一台机器也能接着开。

## 3. 控制器（`controller.ts`）

与 21 点、德州的控制器同形（`tick / nextWakeAt / toState / fromState / handle / getView`），只决定**什么时候**走下一步：

| 节奏（`BAC_TIMING`，毫秒） | |
| --- | --- |
| 下注倒计时 | 15,000（多人桌：第一位真人下注后才开始；单人桌没有倒计时） |
| 停止下注 → 第一张牌 | 1,100 |
| 相邻两张牌 / 第三张牌 | 1,050 / 1,600 |
| 最后一张 → 宣布结果 | 1,200 |
| 自动下一局（多人桌） | 9,000（单人桌等玩家按“下一局”） |

- 多人桌：所有在线的真人都下注或选择“这局不下注”时立即停止下注；到时没下注的人这一局旁观。
- 客户端的操作带着 `round`（局号）与 `actionId`；局号对不上、重复、迟到、超额、负数 / 非整数、替 AI 下注都会被拒绝，余额不变。
- 同桌 AI 只决定押哪里、押多少（普通随机数），它们碰不到牌靴。

## 4. 本地与在线的权威

| | 谁裁决 | 筹码 |
| --- | --- | --- |
| 游客单人 | 浏览器里的同一套控制器（`src/net/localBaccarat.ts`） | 持久金币（本地存档） |
| 登录玩家单人 | 服务器 | 账号的虚拟筹码（数据库） |
| 在线房间 | 服务器 | 桌上筹码（与德州、21 点房间相同，不动账号筹码） |

本地离线模式不以防作弊为目标：牌局与存档都在玩家自己的设备上。在线模式由服务器裁决，客户端只发送“我押闲 100”，
从不发送余额、牌、派彩或胜负。**未公开的牌从不离开服务器**：视图与事件里只有已经翻开的牌，牌靴顺序永远不发送（BACO-02 / BACO-10 检查原始网络数据）。

## 5. 在线事件（`src/core/protocol.ts`，协议版本见 `PROTOCOL_VERSION`）

| 方向 | 消息 | 说明 |
| --- | --- | --- |
| 客 → 服 | `createRoom { settings.gameMode: 'baccarat' }` / `setMode` | 建房时或在大厅切换模式；牌局进行中拒绝切换 |
| 客 → 服 | `bac { cmd, actionId, round }` | `cmd`：`bet { bets } / skip / next / rebuy`；服务器要求局号 |
| 服 → 客 | `bacState { view }` | 只含已经公开的内容；`events` 带递增的 `seq`，客户端据此去重、增量播放 |
| 服 → 客 | `ack { actionId, ok }` | 同一 `actionId` 只执行一次，重发返回同样的结果 |

视图里的事件：`shuffle`、`roundStart`、`bet`、`skip`、`closed`、`card`（第几张、是否第三张）、`natural`、`rule`（补牌 / 停牌及原因点数）、
`result`、`payout`、`left`、`roundEnd`。断线重连、刷新、房主转移、房间保留时间、限流（`bac` 有自己的额度）、Redis 多实例都走原有的房间系统。

## 6. 庄家与台词（`src/core/character/dealers.ts`、`src/core/baccarat/dialogue.ts`）

庄家是现有的动物 + 西装领结，21 点与百家乐共用（文件从 `core/blackjack/` 移到 `core/character/`，旧路径保留转出）。
性格只决定台词、表情和节奏；引擎根本不知道庄家是谁。台词只说已经公开的事情，不会暗示“路单”能预测下一局。

## 7. 结算、经验、统计、成就

- 每局有唯一 `roundId`；服务器结算键 `实例:局:bac:roundId`，本地用同一个结算闸门，重复处理不会重复发奖。
- 奖励规则在 `src/progress/rewards.ts`（`applyBaccaratRound`）：每局 8 经验，净赢再 +12，押和命中再 +40。服务器与游客共用。
- 统计（`Stats.baccarat`，`src/progress/baccaratStats.ts`）：
  - 胜率 = 净赢的局 ÷（净赢 + 净输），打平（例如开和时闲 / 庄退回）单独统计；
  - 押闲胜率 = 押闲赢的局 ÷（押闲的局 − 开和退回的局），押庄同理；押和命中率 = 押和赢的局 ÷ 押和的局；
  - 胜率 ≠ 盈利（庄要抽 5%、和赔 8 倍），净输赢另外显示。
- 数据库迁移 v3 增加 `baccarat` 列（旧存档自动补零）。
- 俱乐部补给（`src/core/refill.ts`）：单人桌的金币 / 账号筹码低于最低下注时免费补到 500，**每天 3 次**（UTC+8 0 点换日，21 点与百家乐共用；账号由服务器在同一个事务里检查并记录，数据库迁移 v4）。在线房间的桌上筹码每个房间每人最多补充 3 次。
- 成就：`bac_first`、`bac_player`、`bac_banker`、`bac_tie`、`bac_10`、`bac_100`、`bac_1000`、`bac_bigwin`、`bac_streak5`。

## 9. 调试（只在开发模式）

网址加 `?debug=1`：调试面板显示局号、阶段、牌靴编号与剩余张数、双方点数、事件序号、演出状态，以及公平性核对
（本局有没有重复 / 无效的牌、补牌是否符合补牌表、派彩是否正确）和本机统计。`npm run dev` 时本地单人桌的下注阶段还有
`Force player / banker / tie / natural / third` 按钮（只在已有牌靴里交换牌的位置，不改规则）。正式构建不包含这些代码。

## 10. 公平性（永久规则）

- 发牌只由随机数决定；没有任何胜率控制、连败补偿、按下注或身份调整的结果。
- 统计、成就、路单只记录结果，从不回头影响发牌。
- 核对工具 `audit.ts` 不调用引擎的规则代码，用补牌表的字面数据从牌重新推算点数、补牌、结果与派彩，用来检查引擎。
- 模拟：`npm run sim:baccarat -- 1000000`，用真正的引擎与加密随机数，逐局独立核对，统计闲 / 庄 / 和的出现率与各区的庄家优势，
  与理论值（闲 44.62% / 庄 45.86% / 和 9.52%；优势 闲 1.24% / 庄 1.06% / 和 14.36%）比较，偏差过大或发现任何错误都以非零状态退出。
- 注意：理论值是“一副全新牌靴的第一局”。整副牌靴一直打到切牌位置时，闲会比理论值高约 0.04 个百分点、庄低约 0.04
  （1,000 万局：闲 44.67% / 庄 45.83% / 和 9.51%，加密随机数与 `Math.random` 结果相同）；每局都换全新牌靴时（300 万局）
  与理论值一致（闲 44.62% / 庄 45.87% / 和 9.51%）。这是牌越发越少时剩余牌组成变化的效应，真实赌场的牌靴也一样，不是洗牌偏差。
  单次 100 万局模拟里出现 2 个标准误左右的波动是正常的。
